## ⚙️ How This Project Works (End-to-End Deep Dive)

This application is built with a decoupled client-server architecture designed for zero-latency execution on commodity hardware.

### 1. Client-Side Recording & Transmission
- **Web Audio API Engine:** The frontend ([app.js](file:///d:/deepfake%20voice/frontend/app.js)) uses the browser's native `AudioContext` and `navigator.mediaDevices.getUserMedia`.
- **Direct PCM WAV Encoding:** Instead of relying on lossy browser compressed formats (like Opus inside WebM, which distorts high frequencies), the client encodes microphone samples directly into an uncompressed **16-bit linear PCM WAV** format with a 16 kHz sample rate.
- **Waveform Canvas:** A `Canvas2D` visualizer runs an active requestAnimationFrame loop rendering real-time oscillating waveforms from the microphone's `AnalyserNode`.
- **Payload Transport:** The resulting audio blob is wrapped in a `FormData` object and transmitted asynchronously via `fetch('/api/predict', { method: 'POST', body: formData })`.

### 2. Backend Ingestion & Audio Normalization
- **Flask REST Endpoint ([app.py](file:///d:/deepfake%20voice/backend/app.py)):**
  - Receives the multipart audio file.
  - Generates a UUID-tagged temporary file in `backend/uploads/` to prevent concurrency collisions.
  - Detects incoming format (`.wav`, `.mp3`, `.ogg`, `.webm`, `.m4a`). If the file is compressed or encapsulated, `pydub.AudioSegment` trans採用s it to a clean WAV container.
  - Automatically unlinks and removes temporary files upon completion in a `finally` block to prevent disk bloat.
- **Singleton Model Lifecycle:** The `DeepfakeDetector` singleton loads `model.pkl` and `scaler.pkl` into memory **once** on application boot. Incoming requests do not incur disk I/O or model deserialization overhead.

### 3. Feature Extraction & Scoring Engine
- The audio is processed through the 230-dimensional acoustic extraction pipeline in [model.py](file:///d:/deepfake%20voice/backend/model.py).
- Features are scaled via the pre-fitted `StandardScaler`.
- The classifier returns posterior class probabilities:
  $$\text{Confidence} = \max(P(\text{Real}), P(\text{Fake})) \times 100\%$$
- Gini-impurity feature importances are summed across feature categories (e.g., LFCC group, MFCC group, Spectral group) and ranked to identify which acoustic traits most influenced the decision.

### 4. Real-Time Dynamic User Interface
- The frontend parses the JSON response and switches from the recording view to the results view.
- Animated SVGs and canvases render:
  - An animated gauge dial depicting the exact confidence percentage.
  - Color-coded badges (Emerald green for **Real**, Crimson red for **Fake**).
  - An acoustic feature breakdown showing which physical anomalies were found in the voice.

## 🎛️ How Audio Frames Are Extracted (Mathematical & Algorithmic Breakdown)

One of the central challenges of audio classification is that raw sound is a **one-dimensional, continuous time series of variable duration**, while classification algorithms require **fixed-size feature representations**. Here is how our frame extraction pipeline solves this:

```text
Continuous Waveform:
  [ ····~·~·~······~·~·~······~·~·~······~·~·~···· ] (e.g. 5 seconds = 80,000 samples)
                            │
               Sliding Window (STFT Framing)
   Frame 1: [---512 samples---]
                 Hop: 256
   Frame 2:      [---512 samples---]
                      Hop: 256
   Frame 3:           [---512 samples---] ... Frame T
                            │
              Apply Hann Window Function w[n]
                            │
            Fast Fourier Transform (FFT) per Frame
                            │
         Frame-by-Frame Spectrogram Matrix: Shape (257, T)
                            │
         Linear Filterbanks (40) + DCT-II Transformation
                            │
          LFCC Feature Matrix: Shape (20 coefficients, T frames)
                            │
        Temporal Derivatives: Delta (20, T) and Delta-Delta (20, T)
                            │
         Collapse Across Time (Temporal Pooling):
           Mean (μ) across T frames  ──► 60 values
           Std  (σ) across T frames  ──► 60 values
                            │
              Total LFCC Features = 120 fixed numbers
```

### The Physics of Speech Framing
Speech is non-stationary: you cannot take a single Fourier Transform of an entire sentence because vocal cords and formants change constantly as consonants and vowels are spoken. However, across a window of **20 to 40 milliseconds**, speech is **quasi-stationary** (the physical shape of the vocal tract remains relatively constant).

### Step 1: Signal Standardization (16 kHz Mono)
- Sound is read as a 1D floating-point NumPy array $y \in [-1.0, 1.0]$.
- Resampled to $f_s = 16,000\text{ Hz}$.
- If audio duration is under 1 second ($< 16,000$ samples), it is zero-padded:
  $$y_{\text{padded}} = [y[0], y[1], \dots, y[L-1], 0, 0, \dots, 0]$$
- Normalized to prevent volume bias: $y = \frac{y}{\max(|y|) + \epsilon}$.

### Step 2: Short-Time Fourier Transform (STFT) Windowing
- **Frame Size ($N_{\text{fft}}$):** $512\text{ samples}$ ($\frac{512}{16000} = 32\text{ milliseconds}$).
- **Hop Size ($H$):** $256\text{ samples}$ ($\frac{256}{16000} = 16\text{ milliseconds}$). This creates a **50% overlap** between successive frames, guaranteeing that transient audio events at frame edges are never lost.
- **Hann Windowing:** Each frame is multiplied element-wise by a Hann window $w[n]$ to taper frame borders to zero and avoid spectral leakage:
  $$w[n] = 0.5 - 0.5 \cos\left(\frac{2\pi n}{N_{\text{fft}}}\right), \quad 0 \le n < N_{\text{fft}}$$
- **STFT Computation:** For each frame $m$:
  $$X[m, k] = \sum_{n=0}^{N_{\text{fft}}-1} y[m \cdot H + n] \cdot w[n] \cdot e^{-j \frac{2\pi k n}{N_{\text{fft}}}}$$
  Where $k \in [0, 1 + \frac{N_{\text{fft}}}{2}] = [0, 257]$ represents the frequency bins from $0\text{ Hz}$ to $8,000\text{ Hz}$ (Nyquist limit).
- **Power Spectrogram:** $S[m, k] = |X[m, k]|^2$.

### Step 3: Linear Filterbank Processing (LFCC)
- 40 linearly spaced triangular filters $H_i[k]$ are generated across the 257 frequency bins.
- Filterbank energies for frame $m$ are calculated via matrix multiplication:
  $$E_i[m] = \sum_{k=0}^{256} H_i[k] \cdot S[m, k] + \epsilon$$
- Log energies are compressed using the Discrete Cosine Transform (DCT Type-II):
  $$c_p[m] = \sum_{i=0}^{39} \log(E_i[m]) \cos\left[\frac{\pi p}{40} \left(i + 0.5\right)\right], \quad 0 \le p < 20$$
  This yields a 2D matrix of shape $(20, T)$, where $T$ is the number of time frames.

### Step 4: Temporal Derivatives (Delta & Delta-Delta)
Static coefficients capture static acoustic timbre. To capture how the speech evolves over time (velocity and acceleration), dynamic deltas are computed across the time frames:
$$\Delta c_p[t] = \frac{\sum_{n=1}^N n \left(c_p[t+n] - c_p[t-n]\right)}{2 \sum_{n=1}^N n^2}$$
Delta-Delta ($\Delta\Delta$) applies the same operation to $\Delta c_p[t]$, producing:
- Static LFCC matrix: $(20, T)$
- Delta LFCC matrix: $(20, T)$
- Delta-Delta LFCC matrix: $(20, T)$

### Step 5: Frame-to-Vector Temporal Pooling (Mean & Std)
Because recording lengths differ (one user speaks for 3 seconds, another for 12 seconds), the number of frames $T$ varies. To produce a fixed-dimension vector for classification:
- For each row $k$ across all frames $t \in [1, \dots, T]$:
  $$\mu_k = \frac{1}{T} \sum_{t=1}^T c_k[t] \quad (\text{Mean: global acoustic baseline})$$
  $$\sigma_k = \sqrt{\frac{1}{T} \sum_{t=1}^T \left(c_k[t] - \mu_k\right)^2} \quad (\text{Std: acoustic variability \& cadence})$$
- Pooling collapses $(20 \times 3, T)$ into:
  $$(20 \text{ static} + 20\ \Delta + 20\ \Delta\Delta) \times 2 (\mu, \sigma) = \mathbf{120\text{ features}}$$
This temporal pooling is applied across all feature groups, generating an exact **230-dimensional feature vector** for any input clip.

## ⚖️ Why We Use This Model vs. Different Models (In-Depth Comparison)

When engineering a deepfake detection system, there are several architectural options. Below is a comparison detailing why the **Calibrated Random Forest Ensemble** was chosen over alternative machine learning and deep learning architectures.

### 1. Why Not 2D-CNNs on Spectrograms (ResNet, EfficientNet)?
- **The Problem:** Treating audio spectrograms as 2D visual images and feeding them into computer vision CNNs (like ResNet-34 or EfficientNet) is a popular academic benchmark, but it suffers from severe real-world failure modes:
  1. **Visual translation invariance does not apply to audio:** In vision, a cat is a cat whether it is at the top or bottom of an image. In audio, shifting energy up or down changes the pitch and formant structure entirely. Standard 2D pooling distorts fundamental acoustic relationships.
  2. **Environmental Overfitting:** Vision CNNs with millions of parameters quickly memorize room impulse responses, background hiss, or specific microphone signatures from the training set rather than genuine neural vocoder artifacts.
  3. **High Resource Demands:** A ResNet model requires tens of megabytes of weights and 10–20× higher CPU inference latency, making real-time browser analysis slow and resource-heavy.

### 2. Why Not End-to-End Raw Waveform Networks (RawNet2, SincNet)?
- **The Problem:** RawNet2 and SincNet process raw waveform samples directly using parametrized sinc filters to avoid manual feature extraction.
  1. **Extreme Sensitivity to Compression:** Raw waveform models depend on fine sample-level phase alignment. When an audio file is saved or transmitted over the internet (via MP3, AAC, or WebM Opus), lossy compression algorithms discard high-frequency phase information. This causes raw waveform networks to produce false positives on compressed human speech.
  2. **Heavy GPU Dependency:** RawNet models are computationally demanding, requiring dedicated GPU instances to achieve practical throughput.

### 3. Why Not Pre-trained Foundation Audio Transformers (Wav2Vec 2.0, Whisper)?
- **The Problem:** Fine-tuning self-supervised foundation models like Wav2Vec 2.0 or HuBERT seems intuitive, but is fundamentally mismatched for deepfake detection:
  1. **Trained for the wrong objective:** Foundation models are pre-trained to extract **linguistic and semantic content** while intentionally ignoring acoustic noise, channel distortion, and vocoder artifacts—the exact physical cues that reveal deepfakes.
  2. **Enormous Footprint:** Wav2Vec 2.0 weights range from 360 MB to 1.2 GB, requiring high memory allocation and several seconds of inference latency per clip on standard CPUs.

### 4. Why Not Recurrent Networks (LSTMs, GRUs)?
- **The Problem:** LSTMs process audio sequentially frame-by-frame.
  1. Sequential recurrence cannot be parallelized as efficiently as tree ensembles during inference.
  2. Deepfake detection is not a temporal sequence decoding problem: detecting whether a voice was synthesized by an AI depends on **acoustic spectral consistency and vocoder artifact distributions across the signal**, not the grammatical order in which phonemes appear. Frame-pooled statistics provide better signal-to-noise ratio.

### 5. Why Not Gradient Boosting (XGBoost / LightGBM)?
- **The Problem:** Gradient boosting builds trees sequentially, where each new tree focuses on the residual errors of the previous trees.
  1. **Outlier Sensitivity:** In audio datasets, audio samples with unusual background noise or odd accents often yield large residual errors. Gradient boosting over-indexes on these noisy edge cases, leading to overfitting on training audio quirks.
  2. **Random Forest's Bagging Advantage:** Random Forest builds 300 decorrelated trees independently using bootstrap aggregation (bagging) and random feature projection ($\sqrt{230} \approx 15$ random features per split). This makes it significantly more resilient to noisy real-world microphone variance.

### 6. Why Calibrated Random Forest Ensemble is the Optimal Choice
1. **Explainable AI (XAI) for Forensics:** Through Gini impurity calculation, our system can immediately attribute its decision to specific acoustic features (e.g., *“51.4% driven by LFCC Vocoder Artifacts, 26.1% driven by MFCC Dynamics”*). Black-box neural networks cannot provide this level of transparency.
2. **Instant CPU Inference:** Evaluates in **25–35 milliseconds**, allowing the web UI to feel instantaneous without requiring expensive GPU servers.
3. **Small Footprint:** The entire trained model is **~650 KB**, making deployment lightweight.
4. **Resilience to Channel & Speaker Overfitting:** Feature sub-sampling ensures no single speaker's pitch or microphone signature dominates the decision tree splits.

## 🧠 Deep Learning Context & Neural Vocoder Artifacts

### What Deep Learning Systems Does This Model Detect?
Modern synthetic voice platforms utilize deep neural architectures consisting of:
1. **Acoustic Models (Text-to-Spectrogram):** Tacotron 2, FastSpeech 2, VITS, Transformer-TTS.
2. **Neural Vocoders (Spectrogram-to-Waveform):** HiFi-GAN, WaveNet, MelGAN, DiffWave, BigVGAN.
3. **Voice Conversion & Voice Cloning:** RVC (Retrieval-based Voice Conversion), ElevenLabs, Tortoise-TTS.

### Deepfake Artifacts Detected by Our System:
- **Phase Incoherence:** Neural vocoders estimate or reconstruct phase from magnitude spectrograms using GAN discriminators. This creates micro-phase cancellations at high frequencies.
- **Checkerboard Artifacts:** Transposed 1D/2D convolutions in neural vocoders leave periodic spectral peaks in linear frequency spectra (captured by LFCC).
- **Absence of Biological Modulation:** Human vocal cords produce micro-variations (jitter and shimmer). Synthetic voices, while smooth, exhibit unnatural pitch stability (captured by Chroma and ZCR dynamics).

## 🔄 Data Augmentation & Training Pipeline

Audio recordings in the real world are captured via varying microphones, rooms, and compression. To prevent the model from failing on phone audio or laptop microphones, [train_model.py](file:///d:/deepfake%20voice/backend/train_model.py) implements physics-based acoustic augmentation:

### 1. Acoustic Augmentation Techniques
- **Room Reflection & Reverb Simulation:**
  $$y_{\text{reverb}}[t] = y[t] + \alpha \cdot y[t - \tau]$$
  Where delay $\tau \in [15\text{ ms}, 35\text{ ms}]$ and decay $\alpha \in [0.12, 0.25]$.
- **Microphone Frequency Attenuation:** A 2nd-order low-pass Butterworth filter with cutoff between 6.8 kHz and 7.8 kHz simulates telephony and low-cost headset frequency limits.
- **Ambient Noise Floor Injection:** Low-amplitude Gaussian white noise ($\mathcal{N}(0, \sigma^2)$) simulates real-world environments.

### 2. Validation & Evaluation
- **Stratified Train/Test Split:** 80% train, 20% test, preserving class ratios.
- **StandardScaler Normalization:** Fits zero-mean and unit-variance scaling on training features; applied identically at test time.
- **5-Fold Cross Validation:** Validates model stability across rotated data folds.

   - Select your GitHub repository and click **Import**.

3. **Configure Environment Variables (Recommended for Heavy ML packages):**
   - In the project configuration screen (or later under **Settings > Environment Variables**):
   - Add:
     - **Name:** `VERCEL_SUPPORT_LARGE_FUNCTIONS`
     - **Value:** `1`
   *(This unlocks Vercel's Fluid Compute 5GB serverless function bundle support for `scipy` and `librosa`)*

4. **Click Deploy:**
   - Vercel will install dependencies from `requirements.txt`, bundle `api/index.py`, and publish your UI at `https://<your-project>.vercel.app`.
